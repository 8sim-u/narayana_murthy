The shape of the thing

A Windows edge node runs YOLOv8n person detection with ByteTrack tracking, then HTTP-POSTs a JSON detection event to a FastAPI service. That service runs a rule evaluator, persists the event to PostgreSQL through SQLAlchemy, and exposes a read API. The dashboard folder is empty, so nothing consumes those events yet.

02  ·  What Is Missing, Ranked

Everything below was confirmed by reading the code, not inferred from the README. Severity reflects risk to a real deployment, not effort.

SeverityFindingWhy it matters
CRITICAL Plaintext database password committed in backend/tests/conftest.py A working PostgreSQL credential for user surveillance_app on surveillance_dev sits in git history on a public repo. It directly violates the project's own rule #3. Must be rotated and purged from history — rotation alone is not enough while the old value is indexed.
CRITICAL Zero authentication or authorization on any endpoint Anyone who can reach port 8000 can inject fake detections and read the entire location history of every person the cameras have seen — who was where, at what time. For a system whose whole output is human-movement data, this is the single largest exposure.
CRITICAL No privacy layer anywhere in the pipeline Raw video is processed at the edge, but the design has no anonymisation, no retention limit, and no purpose limitation. A workplace monitoring system without these is not deployable in most jurisdictions (see §05).
HIGH README rule #2 (source="simulation") is unimplemented No source field exists in the schema, model, or database. The project's stated safeguard against confusing simulated data with real detections does not exist — which is precisely the failure that rule was written to prevent.
HIGH frontend/, shared/, docs/ are empty Half the declared architecture is a placeholder. No dashboard, no shared schemas or simulation data, no documentation. The "simulation-first" approach has no simulation.
HIGH Vision dependencies are undeclared Nothing in any requirements file mentions ultralytics, opencv-python, torch, or requests. Confirmed: importing the vision modules from a clean install fails with ModuleNotFoundError. The vision half of the repo cannot be reproduced from the repo.
HIGH Two competing backends vision/bridge.py re-implements POST /event with its own in-memory buffer that silently drops everything past 1000 events. Two divergent sources of truth for the same endpoint, and the edge node actually points at the bridge, not the real backend.
MEDIUM Hardcoded LAN addresses Camera URLs and the bridge host are literals in multicamera.py. Re-pointing at a new network means editing source.
MEDIUM Rule engine is a single if One rule, one hardcoded string comparison. No configuration, no zone geometry, no time dimension — so no loitering, dwell, occupancy, or capacity logic is possible.
MEDIUM No push channel No WebSocket, so any dashboard must poll. Alerting latency is bounded by the poll interval.
MEDIUM No migrations, no CI, no container Tables are created by create_all; the first schema change will be a manual, error-prone deploy. No pipeline guards the 12 passing tests.
MEDIUM cv2.imshow in the detection loop Requires a desktop session. Breaks headless and server deployment, and blocks a GPU throughput path.
LOW No retention policy; JSON blob columns Detection rows accumulate forever, and objects/alerts are unindexed JSON — fine now, painful at millions of rows.

Do this before anything else

Rotate the surveillance_app database password, remove the literal from conftest.py (already done in this working copy), and scrub the value from git history with git filter-repo or BFG. Then add a secret-scanning step to CI so it cannot recur. Until the credential is rotated, every other improvement is secondary.

03  ·  The Vision

From counting people to understanding space

Today WAMSS answers "was a person detected in front of camera 2?". The defensible long-term product answers "how is this building actually used, and is it safe?" — without ever identifying anyone. That shift from individual detection to anonymous aggregate intelligence is both the commercial opportunity and the compliance strategy. The moment the system can name a person, it becomes a regulated biometric surveillance tool; as long as it cannot, it stays a space-analytics product.

05  ·  The Track That Cannot Be Skipped

This is a workplace monitoring system. That is not a footnote — it determines whether the product is legal to ship. The privacy work has to run in parallel with the engineering, not after it.

Regulatory reality

  • India — DPDP Act 2023. Employee footage is personal data. It requires notice and consent, purpose limitation, data minimisation, storage limitation, and security safeguards. Given the project's naming and origin, this is the most likely governing regime.
  • EU / UK — GDPR. Systematic monitoring of a workplace triggers a mandatory Data Protection Impact Assessment under Art. 35. In Germany and France, works councils or employee representatives must be consulted before deployment.
  • Biometric identification without an explicit legal basis is prohibited or heavily restricted in most of these jurisdictions — which is exactly why the ReID work in Horizon 2 must stay anonymous and non-identifying.

Principles to build in from the start

  • No covert monitoring. Visible signage wherever a camera operates.
  • Aggregate by default, individual by exception — and log every exception.
  • Hard retention caps. Detection rows should expire automatically, not by policy document.
  • Measure model bias. Computer-vision person detection performs unevenly across skin tone, body type, and clothing. Publish per-group error rates and never let detection output feed an individual performance decision.
  • Respect the chilling effect. Monitoring measurably damages trust and wellbeing. Scope the product to safety and space utilisation — explicitly not to productivity policing. A "productivity score" derived from this data would be both ethically indefensible and, in several jurisdictions, unlawful.

Gate: no real camera should be connected until a privacy policy and a DPIA exist.

07  ·  If You Only Do Ten Things

  1. Rotate and purge the leaked database credential. Add secret scanning to CI. Nothing else matters until this is done.
  2. Put authentication in front of every endpoint. API keys for edge nodes, JWT with roles for people.
  3. Implement the source field the README already promises, so simulation can never be confused with reality.
  4. Delete vision/bridge.py and point the edge node at the real backend. One source of truth.
  5. Declare vision dependencies in their own requirements file so the CV half is reproducible.
  6. Build the dashboard — a React + TypeScript view with live occupancy and an alert feed. Without a consumer, none of the data has value.
  7. Add the simulation harness in shared/ that emits labelled synthetic events. This is the project's stated approach; it currently does not exist.
  8. Adopt Alembic and Docker Compose so the stack is reproducible and schema changes are safe.
  9. Replace the single hardcoded rule with a configurable rule engine supporting zone geometry and time windows.
  10. Write the DPIA and privacy policy before any real camera is connected. This is a deployment gate, not documentation.

08  ·  Bottom Line

The foundation is sound. The backend is clean, typed, tested, and genuinely works — 12 tests passing, validation and error handling done properly, secrets kept out of the app config. That is a better starting point than most prototypes.

But roughly two-thirds of the declared system does not exist yet, and the parts that do carry two serious exposures: a committed database credential and a completely unauthenticated API that exposes human movement data. Those are days of work, not months — and they should happen before any new feature.

The interesting opportunity is the pivot already implied by the architecture: keep inference on the edge, let only anonymous metadata travel, and sell space intelligence rather than person surveillance. That choice is what makes this defensible — legally, ethically, and commercially. Made deliberately now, it is an advantage. Made by accident later, it is a liability.
